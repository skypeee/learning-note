# 通用嵌入式设备管理平台 — PRD v0.1

> 创建：2026-04-19 | 状态：草稿 | 作者：项目团队

---

## 一、产品定位

**一句话**：面向嵌入式设备的通用管理云平台，提供设备接入、状态监控、远程控制和数据可视化。

**通用设计原则**：
- 不绑定特定设备类型，所有功能按**设备能力**动态展示
- 有 GPS 的设备显示地图和轨迹回放，无 GPS 的默认不展示
- 避免依赖单一设备类型，从架构层做到多设备兼容

---

## 二、目标用户

面向所有嵌入式/IoT 设备的管理需求，包括但不限于：
- 无人机、机器人等移动设备
- 传感器节点、工控设备
- 开发板、嵌入式终端

---

## 三、MVP 核心能力

### 3.1 设备接入与注册
- 设备通过 MQTT 协议上线注册
- 心跳保活机制（定时发送心跳，超时判定离线）
- 设备基本信息管理（名称、型号、固件版本、能力标签）

### 3.2 状态监控
- 实时状态：在线/离线/异常
- 设备属性遥测数据上报（温度、电压、信号强度等）
- 事件告警（自定义阈值，异常触发）

### 3.3 位置追踪（GPS 能力设备）
- GPS 坐标上报 + 地图实时展示
- 历史轨迹回放
- 地理围栏（V2 规划）

### 3.4 远程控制（设备影子）
- **期望状态（Desired）**：用户下发目标配置
- **上报状态（Reported）**：设备实际状态
- 状态差异对比 + 自动同步
- 设备离线时缓存配置，上线后自动下发

### 3.5 Web 控制台
- 设备列表（表格 + 状态标签 + 搜索）
- 设备详情页（状态卡片 + 遥测实时刷新 + 参数面板）
- 遥测数据可视化（折线图、仪表盘）

---

## 四、暂不包含（V2+）

| 功能 | 原因 |
|------|------|
| 多租户 / 计费 | MVP 阶段单租户足够 |
| AI 日志分析 | 数据积累后再做 |
| 航线规划 / 任务下发 | 无人机专属，不符合通用定位 |
| OTA 升级 | 涉及固件分发，复杂度高 |
| 地理围栏 | 位置类功能的 V2 扩展 |

## 五、技术架构

```
[设备端] ──MQTT──→ [Go 后端] ──WebSocket──→ [React 前端]
                     │
                   Redis（设备状态缓存、在线状态）
                     │
                   MySQL（遥测历史、设备信息）
```

| 组件 | 选型 | 理由 |
|------|------|------|
| 后端 | Go | 高并发场景，goroutine 天然适合 MQTT 连接管理 |
| 前端 | React + TypeScript | 统一技术栈，类型安全 |
| 设备通信 | MQTT | IoT 标准协议，轻量、低带宽 |
| 前后端通信 | WebSocket | 实时遥测数据推送 |
| 缓存 | Redis | 设备在线状态、实时遥测、影子缓存 |
| 持久化 | MySQL | 设备信息、遥测历史（后期分表） |

## 六、认证与授权（SSO）

### 6.1 架构设计

```
                    ┌─────────────────────┐
                    │   Nginx / Gateway   │
                    │   (统一入口)         │
                    └────────┬────────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
        ┌─────▼─────┐ ┌─────▼─────┐ ┌──────▼──────┐
        │ auth      │ │ device    │ │ telemetry   │
        │ service   │ │ service   │ │ service     │
        │ :8001     │ │ :8002     │ │ :8003       │
        └─────┬─────┘ └───────────┘ └─────────────┘
              │
              ▼
        ┌─────────────┐
        │ Redis       │  ← session 黑名单 / token 状态
        └─────────────┘
        ┌─────────────┐
        │ MySQL       │  ← users / tenants / oauth_clients
        └─────────────┘
```

- 认证中心：独立 `auth-service`，负责登录/登出/注册/token 签发
- 业务服务：各服务通过中间件统一验签 JWT，从 token 提取 `user_id` 和 `tenant_id`
- 多租户：JWT 携带 `tenant_id`，各服务查询自动过滤 `WHERE tenant_id = ?`

### 6.2 JWT 结构

```json
{
  "sub": "1001",
  "tenant_id": "1",
  "roles": ["admin"],
  "iat": 1713500000,
  "exp": 1713503600,
  "jti": "uuid-unique"
}
```

| 字段 | 含义 |
|---|---|
| sub | 用户 ID |
| tenant_id | 租户 ID（数据隔离用） |
| roles | 权限角色 |
| exp | 过期时间（1 小时） |
| jti | 唯一 ID，登出时查黑名单用 |

### 6.3 核心流程

**登录**：前端 POST `/login` → 验证通过 → 返回 `access_token`（JWT）+ `refresh_token`
**鉴权**：各服务通过 Header `Authorization: Bearer <token>` 验签，失败返回 401
**刷新**：401 时前端自动用 `refresh_token` 换新 token，失败则跳登录页
**登出**：token 加入 Redis 黑名单（TTL = token 剩余有效期），各服务验签前先查黑名单

### 6.4 设备端认证（独立体系）

设备通过 MQTT 接入，使用设备凭证（device_id + secret），**不走 Web SSO 流程**。

### 6.5 演进路线

| 阶段 | 方案 | 说明 |
|------|------|------|
| MVP | 自研 auth-service + JWT + Redis 黑名单 | 最小可用 |
| V2 | 接入 Keycloak / Casdoor | 免去自研维护成本 |
| V3 | OIDC 对外 + MFA | 提供 SSO 给第三方集成 |

## 七、设备能力模型

设备注册时声明自身能力，平台按能力动态渲染 UI：

```json
{
  "device_id": "dev-001",
  "capabilities": ["telemetry", "gps", "camera", "param_control"],
  "properties": {
    "model": "Pixhawk 6C",
    "firmware": "ArduPilot 4.5"
  }
}
```

| 能力标签 | 前端展示 | 说明 |
|----------|---------|------|
| `telemetry` | 遥测数据面板 | 基础能力，所有设备都有 |
| `gps` | 地图 + 轨迹回放 | 有 GPS 的设备才有 |
| `camera` | 视频流窗口 | 有摄像头的设备才有 |
| `param_control` | 参数读写面板 | 支持远程配置的设备才有 |

## 八、验收标准

- [ ] 设备能通过 MQTT 上线，心跳正常
- [ ] 前端能实时显示设备在线状态
- [ ] 遥测数据 WebSocket 推送延迟 <500ms
- [ ] GPS 设备能在地图上看到实时位置和轨迹
- [ ] 设备影子：远程修改参数后设备能收到
- [ ] 无 GPS 设备不展示地图相关 UI
