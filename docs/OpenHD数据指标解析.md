# OpenHD 链路数据指标解析

> 本文档梳理 OpenHD 前端界面各 Tab 页显示的数据字段、底层对应消息（msg_id）、物理含义及典型问题排查逻辑。
> **核心协议**：`wifibroadcast`（单向广播，无 ACK 机制）
> **数据来源**：`msg_id=1211 LINK_STATS` + `1212 VIDEO_AIR` + `1213 FEC` + `1216 WIFI_CARD` + `1227 SYS_STATUS1`

## 五、核心原理：Loss 丢包率的计算与方向性

### 1. 为什么地面端 Loss 代表视频流，天空端 Loss 代表指令？
这与 `wifibroadcast` 的**单向广播特性**直接相关：

```text
天空端 TX ──WiFi广播──▶ 地面端 RX  （视频、遥测数据）
地面端 TX ──WiFi广播──▶ 天空端 RX  （指令、参数数据）
```
双方**没有 ACK 确认机制**，各自只统计 **“自己实际收到了多少包”**。

### 2. Loss 计算公式
```math
Loss = (预期应收到的包数 - 实际收到的包数) / 预期应收到的包数 × 100%
```
`wifibroadcast` 的数据包自带递增序列号。接收端通过检测序列号的**跳跃（Gap）**来判断丢包数量。

### 3. 方向映射表
| 统计项 | 测量方向 | 实际携带的数据类型 |
|:---|:---|:---|
| **天空端 Loss** | 地面端 → 天空端（RX） | 遥控指令、参数配置、心跳 |
| **地面端 Loss** | 天空端 → 地面端（RX） | 实时视频、飞控遥测、电池状态 |

## 六、典型问题排查：为何天空端 Loss 高 (40-50%)，地面端 Loss 低 (<10%)？

这是典型的**上行链路弱于下行**现象，常见原因如下：

1. **📡 视频流量压制**：天空端持续高码率发送视频包，占满无线信道空气时间（Airtime）。地面端发送的少量指令包极易被视频包碰撞或覆盖，导致上行丢包率高。
2. **📉 MCS 2 + 40MHz 频宽限制**：MCS 2 属于较低阶调制（抗干扰强但速率低），配合 40MHz 频宽时，若天空端天线增益不足或方向未对准，上行信号衰减会非常明显。
3. **🔋 地面端 TX 功率不足**：地面站（通常为笔记本/平板/手持设备）的 WiFi 网卡发射功率普遍低于天空端（通常接外置高增益天线+PA放大器）。物理层信号弱，导致天空端 RX 解调失败率高。
4. **🌊 同频干扰**：5.8GHz 频段在开阔地或城市环境中易受其他 WiFi 网络或图传设备干扰，进一步恶化弱信号方向的上行链路。

> 💡 **优化建议**：若需降低天空端 Loss，可尝试降低天空端视频码率（减少 Airtime 占用）、提高地面端 WiFi 发射功率、或为地面端更换高增益定向天线。
